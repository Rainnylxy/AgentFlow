设计 Section 6：交互模型——你作为导演

自然语言驱动的协作模式，你在每个阶段都能随时介入、调整、回退

交互模式一览

👁️ 审核模式

Pipeline 每个阶段完成后暂停，展示结果等你确认

「风格判断为古风，人物：苏墨、老者、黑猫。
确认为 3 个场景。继续吗？」
你可回复："继续" / "场景太少，拆成 5 个" / "风格不对，应该是日式"

🔧 微调模式

针对单个格子或元素做精准调整，不影响其他已有内容

「第三格的镜头从俯视改成仰视」
「苏墨的台词太软了，改成更有锋芒的」
「这格的色调偏暖了，重绘成冷色调」
只影响指定目标，其余格子保持不变

🔄 重做模式

对不满意的结果整体重来，但保留已有的偏好信息

「场景 2 整体重做，节奏太拖了」
「这个角色定妆照不行，换个角度重新生成」
重做时自动注入已有的反馈记忆，避免重复踩坑

导演指令集（部分示例）

自然语言 → Agent 翻译 → Pipeline 操作
你说的话 Agent 理解 Pipeline 操作

"全部确认，继续下一章" 保存当前章 → 加载下一章文本 角色库持久化 → 反馈记忆持久化 → 新 Pipeline 实例

版本历史与回退机制

数据总线快照

每个 Pipeline 阶段完成后自动创建快照（完整数据总线状态），存储在 .project/snapshots/。回退 = 恢复到任意历史快照。

操作日志

记录所有用户操作和 Pipeline 动作：{timestamp, action, target, before, after}。支持 undo/redo 栈。

分支实验

允许从任意快照分叉：
"从场景3的分镜分两个分支，A 分支用古风、B 分支用日式，对比看看"

交互界面形态

Agent 交互层可以对接不同的前端：

💬 CLI 对话
第一版，终端自然语言交互
🌐 Web UI
图片预览 + 并排对比 + 点击选择
🔌 IDE 插件
VS Code 侧边栏，边写小说边预览漫画

第一版建议 CLI 对话模式——交互模型不变，后续升级 UI 只是换壳。

交互模型设计为自然语言驱动——你像导演一样说话，Agent 翻译为精确的 Pipeline 操作。审核/微调/重做三种模式覆盖所有协作场景。你觉得这个交互方式顺手吗？
