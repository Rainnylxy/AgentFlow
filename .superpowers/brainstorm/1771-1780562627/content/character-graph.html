设计扩展：人物关系知识图谱

从"角色列表"升级为"角色关系网"——系统理解谁爱谁、谁恨谁、谁是卧底

为什么需要知识图谱？

❌ 纯列表的问题
  • 苏墨和将军是什么关系？需要每次从原文推理
  • 黑猫是宠物还是化身？系统不知道
  • 两人同框时，站位远近/表情互动全凭猜
  • 情感变化（从友变敌）无法追踪
✅ 知识图谱的效果
  • 分镜时自动推断角色间距和互动模式
  • "仇人相见"→ 自动给特写、紧张构图
  • "暗恋对象出现"→ 自动加微妙眼神和氛围
  • 跨章节追踪关系变化曲线

关系图谱数据模型

节点 = 角色，边 = 关系，属性 = 关系细节
CharacterGraph {
  nodes: CharacterNode[]         // 角色节点
  edges: RelationshipEdge[]      // 关系边
  timeline: RelationEvent[]       // 关系变化事件
}

CharacterNode {
  id, name, role_type,           // role_type: "protagonist" | "antagonist" | "supporting" | ...
  faction,                       // 所属势力/阵营
  importance: 1-10,              // 重要程度（影响出场频率和特写优先级）
  first_appearance_chapter,
  status: "active" | "dead" | "missing" | "unknown",
  character_sheet_ref            // → CharacterSheet.id
}

RelationshipEdge {
  from, to,                      // → CharacterNode.id
  relation_type,                 // "血缘" | "爱情" | "友情" | "敌对" | "师徒" | "主仆" | "利用" | ...
  sub_type,                      // "暗恋" | "杀父之仇" | "青梅竹马" | "背叛" | ...
  intimacy: -10 ~ +10,           // 亲密度：-10(不共戴天) ~ +10(生死相依)
  power_dynamic,                 // "平等" | "A主导" | "B主导" | "互相制衡"
  public_knowledge: bool,        // 这层关系是公开的还是隐藏的？
  current_tension,               // 当前张力："和谐" | "紧张" | "暧昧" | "一触即发"
  shared_history: string,        // "三年前A背叛了B"——影响互动模式
  manifested_since_chapter,      // 关系何时建立
}

RelationEvent {              // 追踪关系变化
  timestamp, chapter,
  edge: (from, to),
  change: { field, old_value, new_value, trigger_event }
  // 例：{ field: "intimacy", old: 5, new: -8, trigger: "A发现B是卧底" }
}

图谱如何影响分镜

关系模式 图谱推理 自动影响的分镜参数
intimacy ≥ +7
（生死相依）		 两人关系极亲密，同框时距离近 → 双人中近景、眼神交流、柔和光线
→ dialogue 语气温和
→ sd_prompt 追加 "close together, warm atmosphere"
intimacy ≤ -7
（不共戴天）		 势不两立，同框必对峙 → 斜线/对峙构图、低角度仰拍
→ 特写眼神交锋
→ sd_prompt 追加 "tense standoff, dramatic shadows"
power_dynamic
"A主导"		 A 是关系中的上位者 → A 取仰拍（显高大）、B 取俯拍（显弱小）
→ A 占画面更大比例
public_knowledge
= false		 隐藏关系（卧底/暗恋/秘密同盟） → 公开场合两人站远、表情刻意
→ 只在对视瞬间流露真实情绪"微表情特写"
→ 用阴影或构图暗示隐藏关系
current_tension
"暧昧"		 感情未明朗，微妙阶段 → 避免直视、多侧脸和偷看视角
→ 对话气泡小而靠边
→ sd_prompt 追加 "shy glance, cherry blossoms, soft focus"

图谱构建与更新流程

📖 新章节 → LLM 提取人物互动 → 匹配已有节点 / 新建节点 → 更新/新建边（含属性） → 检测变化 → 写入 RelationEvent → 🎯 你审核图谱变化
每章完成后，LLM 自动提取本章中的人物关系变化 → 生成图谱更新提案 → 你确认后写入

存储方式

第一版：JSON 内嵌

CharacterGraph 作为 project.json 的一部分，节点≤50 人物时完全够用。手工编辑也方便。

优点：简单、可 git 版本控制
进阶版：图数据库

Neo4j / Kuzu(嵌入式) — 人物>50 或跨小说联动时升级。支持复杂图查询（"找出所有被背叛过的角色"）。

优点：复杂查询、可视化、扩展性强

第一版用 JSON，数据模型预留好升级路径——节点和边的 schema 与图数据库兼容。
