设计 Section 5：角色一致性方案

这是小说→漫画最核心的技术挑战——同一个角色在每一格里都要像同一个人

四层一致性防线

🔴 第一层：Character Sheet 定妆（生成前·质量控制）
每个角色生成 1 张定妆照 (Reference Image)，作为后续所有生图的视觉锚点。
定妆照要求：正面半身、中性表情、完整服饰、纯色背景——方便作为 ControlNet/IP-Adapter 输入。
用户审核通过后锁定 → 写入角色库 → 后续不可随意更改（除非主动"改妆"）。
🟡 第二层：Prompt 约束（生成时·文本对齐）
每个角色的 sd_trigger_words 自动注入所有该角色出现的格 prompt 中。
例如苏墨的触发词："su_mo, lean swordsman, sharp jawline, long black hair tied up, deep piercing eyes, worn grey robes, rusty iron sword"
触发词由 ② 角色设计阶段生成，经用户确认后写入角色库。用户每次修正都会更新触发词（反馈记忆）。
🔵 第三层：Reference Image 传参（生成时·视觉锚定）
生图 API 调用时传入定妆照作为参考图。根据所选云平台能力选择策略：
有 IP-Adapter → 传 reference_image + adapter_weight(0.7-0.85)
有 Reference-only → 传 reference_image + style_fidelity(0.6-0.8)
只有 img2img → 传 reference_image + denoising_strength(0.5-0.7)
都没有 → 纯靠 prompt 约束（第四层兜底）
🟢 第四层：一致性检测（生成后·自动验证）
生成图片后自动与定妆照做相似度比对（可用 CLIP/ViT 嵌入余弦相似度）。
低于阈值(如 0.75)的自动标记 ⚠️ → 提示用户确认或自动触发重绘。
用户手动标记"不像"的图片 → 记录到反馈记忆 → 优化触发词。

角色生命周期

一个角色从出场到终章的完整管理流程
📖 首次出场 → LLM 提取外貌 → 生成定妆照 → 🎯 你审核锁定
↓
💾 写入角色库：{name, sheet, reference_image, trigger_words, locked: true}
↓
每次出场：自动注入 trigger_words + 传参考图生图
↓
用户修正 → 🧠 反馈记忆更新 trigger_words
↓
🔁 新章节：从角色库加载 → 复用已锁定的外貌（可选"改妆"）

特殊场景处理

场景 问题 方案
新角色中途登场 第 5 章才出现的人物，之前没有定妆照 触发 ② 角色设计阶段，追加到角色库，不影响前面已生成的图片
角色外貌变化 角色受伤/变装/年龄变化/黑化 创建角色"变体"（如 "苏墨·重伤"），从原角色继承基础外貌，叠加变更描述
远景/背影/剪影 看不清脸，一致性检查会误报 分镜标记 camera_angle 为远景/背影时，跳过人脸相似度检查，只验证服饰颜色/体型
群像场景 多角色同框，生图难度翻倍 分镜标记为群像 → 使用更强的模型 + 降低每角色一致性期望 → 用户手动审核权重提高

四层防线从生成前、生成中、生成后三个阶段锁定角色一致性。你觉得这个方案能解决"每格都要像同一个人"的问题吗？
