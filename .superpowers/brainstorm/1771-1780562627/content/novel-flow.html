用户传入小说后的完整操作

StoryGraph v2 — 6 类节点、9 种边、因果事件链

Phase 1：加载 & 解析

📖 用户传入小说文件 (.txt)

 ┌─ load_novel(file_path)
 │   │
 │   ├─ ① 编码检测 → _read_text_file()
 │   │     UTF-8 → UTF-16 → GBK → GB18030 → latin-1
 │   │
 │   ├─ ② 注册表查缓存 → find_novel(file_path)
 │   │     ├─ [命中] SHA256 未变 → Novel.load(novel.json) → 恢复图谱 → 返回
 │   │     └─ [未命中] ↓
 │   │
 │   ├─ ③ 解析章节 → parse_novel_chapters(text)
 │   │     正则匹配: "第X章" / "Chapter X" / 数字顿号
 │   │     → ChapterInfo[] { index, title, content, word_count }
 │   │
 │   ├─ ④ 构建 StoryGraph → extract_story_graph_from_text()
 │   │     采样 10 章(均匀分布), 每章前 1500 字
 │   │     → 一次 LLM 调用提取 6 类实体:
 │   │       人物 | 事件 | 地点 | 组织 | 物品 | 章节
 │   │     → 9 种边:
 │   │       人物关系 | 出场 | 参与事件 | 事件发生于章节
 │   │       事件位于地点 | 属于组织 | 拥有物品
 │   │       事件因果 | 地点层级
 │   │
 │   ├─ ⑤ 持久化
 │   │     novel.json (含 story_graph) → 项目目录
 │   │     register_novel() → novel_registry.json (SHA256 指纹)
 │   │
 │   └─ ⑥ 返回章节列表 → Agent 显示给用户

Phase 2：选章 & 图谱增量

👤 用户: "生成第 3 章"

 ┌─ select_chapter(3)
 │   ├─ 继承全书角色库 (novel.characters)
 │   ├─ 继承全书风格 (novel.style_profile)
 │   │
 │   ├─ 增量更新图谱 (如果 last_updated_chapter < 3)
 │   │   → update_story_graph_with_chapter()
 │   │   → 返回: new_characters, new_relationships,
 │   │           updated_relationships, new_events
 │   │
 │   └─ 创建 ChapterData → 进入管线

Phase 3：漫画生成管线

 ┌─ analyze_text(text)
 │    LLM 分析 → 风格(gufeng/manga/webtoon) + 人物预览 + 基调
 │    detect_style() 自动判断风格
 │
 ├─ design_characters()
 │    注入 StoryGraph 上下文 → LLM 生成 CharacterSheet[]
 │    新角色自动同步到 Novel.characters (全书角色库)
 │
 ├─ extract_scenes()
 │    LLM 拆分为 3-8 个叙事场景
 │
 ├─ storyboard_scene(scene_id) × N
 │    注入 StoryGraph 分镜指导:
 │      intimacy → 空间距离 | power_dynamic → 镜头角度
 │      public_knowledge → 表情克制 | tension → 氛围提示
 │    sd_prompt 自动注入: 风格基座 + 角色触发词 + 画幅比例
 │
 ├─ generate_images(scene_id=0)
 │    云端 API / 占位图兜底
 │
 ├─ compile_comic()
 │    条漫纵向拼接 + 场景标题 + 对话框 + 格编号
 │
 └─ save_project()
      持久化 novel.json + chapter_data.json
      更新注册表

Phase 4：交互式查询 & 对话

👤 用户可以随时穿插:

 ┌─ ask_plot("苏墨为什么回来？")
 │    关键词提取 → 搜索全书章节
 │    注入 StoryGraph 上下文 + 匹配章节片段 → LLM 回答
 │
 ├─ query_graph()
 │    返回完整 StoryGraph: persons, events, locations, orgs, items
 │    因果链(event_relations) + 变化时间线(timeline)
 │
 ├─ query_character_relations("苏墨")
 │    返回所有关系 + 分镜指导
 │
 ├─ query_events("苏墨")   [NEW]
 │    角色的完整事件时间线
 │
 ├─ "继续第 5 章" → select_chapter(5) → 管线
 │
 ├─ "苏墨的眼神不够冷，重做" → Agent 重新调用 design_characters
 │
 └─ quit → 退出循环

StoryGraph 数据结构

NetworkX MultiDiGraph — 异构知识图谱
节点类型 Key 格式 字段 关联边
👤 person person:苏墨 role_type, faction, importance, status, description relationship, appears_in, participates, belongs_to, owns
⚡ event event:三年之约 event_type, chapter_start/end, location, cause, effect, participants, importance participates, occurs_in, located_at, event_relation
📍 location location:长安城 location_type, parent, description, factions, is_destroyed located_at, location_hierarchy
🏛️ org org:将军府 org_type, leader[], members[], base, status belongs_to
⚔️ item item:锈剑 item_type, grade, owner_history, abilities, source owns
📖 chapter chapter:3 index, title, summary, key_events[], appearing_characters[] appears_in, occurs_in
