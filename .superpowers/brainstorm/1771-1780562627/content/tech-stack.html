设计 Section 7：技术选型与数据模型

最后一块拼图——用什么技术实现，数据在各阶段如何流转

技术选型

模块 推荐方案 理由
🖥️ 运行环境 Python 3.10+ LLM SDK、图像处理库生态最成熟
🧠 LLM（分析/分镜/排版） DeepSeek / Claude / GPT-4o 需要长上下文（整章文本）+ 结构化输出能力。通过统一 Adapter 层切换，不绑定单一模型
🖼️ 生图 API Stability AI / Replicate / 即梦 优先选支持 Reference Image 的云 API。通过 ImageGenAdapter 抽象，支持多 provider 切换
👤 角色一致性 IP-Adapter (via Replicate) / 即梦角色参考 根据所选云平台的能力选用，无参考图能力的降级为纯 prompt 约束
🔍 一致性检测 CLIP / DINOv2 嵌入 + 余弦相似度 轻量级，不需要 GPU，可在 CPU 上跑推理
🎨 排版渲染 Pillow (PIL) + 自建排版引擎 格阵计算 + 对话框叠加 + 特效字渲染。初期够用，后期可换 ReportLab/Skia
💾 数据持久化 JSON 文件 + 项目目录结构 人可读、可版本控制、无需额外数据库。项目文件即数据文件
🧠 反馈记忆 JSON profile + LLM 规则提取 第一版不引入向量数据库，用 LLM 从反馈文本中提取结构化偏好写入 JSON

API 适配层设计

所有外部依赖通过抽象的 Adapter 接口访问，方便切换 provider：

LLMAdapter
.chat(prompt, schema?) → structured_output
.analyze_text(text) → Analysis
.generate_storyboard(scene, chars) → Panel[]
实现：DeepSeekAdapter / ClaudeAdapter / GPTAdapter
ImageGenAdapter
.generate(prompt, ref_image?, style_profile) → Image
.generate_with_character(prompt, char_sheet) → Image
实现：StabilityAdapter / ReplicateAdapter / JimengAdapter

技术选型强调"适配层"模式——LLM 和生图 API 都通过抽象接口访问，方便后期切换。数据模型以 Project 为顶层，覆盖了从角色到分镜到用户偏好的所有实体。这是设计部分的最后一个模块，整体都 OK 吗？
